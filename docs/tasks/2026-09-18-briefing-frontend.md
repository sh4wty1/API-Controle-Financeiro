# Briefing para a sessão do front

**Por quê:** o usuário decidiu fazer o front em projeto separado (Bun + React + TypeScript + Vite, em vez do `static/` do Spring) e pediu um `.md` que oriente a sessão do Claude nesse outro projeto, que ainda não existe.
**O quê:** `docs/frontend-briefing.md`, pra copiar como `CLAUDE.md` na raiz do projeto do front. Traz: papel de tutor (a regra "IA não escreve código" estendida ao front, a pedido de "me ensina tudo"), stack decidida, ambiente de dev (túnel pro banco na VPS, proxy do Vite com prefixo `/api`), contrato da API (rotas, DTOs, status, formato de erro), roteiro em 8 passos com critério de conclusão e pegadinhas.
**Como:** leitura de `LancamentoController`, `CategoriaController`, `GlobalExceptionHandler` e dos DTOs pra copiar o contrato real; escrita seguindo o guia de documentos pra agentes (só o que a sessão do front não consegue descobrir olhando o próprio repo). Nenhum código da API alterado.
**Verificação:** contrato conferido contra o código por leitura. `bun 1.3.14` e `node v24.18.0` presentes na máquina. Na hora de escrever, nada tinha sido executado contra a API (banco fora do ar), então o formato do `Page` e os dois 500 (`valor <= 0` e `DELETE` de categoria com lançamentos) eram inferências. Depois foram confirmados contra o banco real e o briefing foi atualizado (ver `2026-09-18-static-teste-api.md`).
**Pendências:** o usuário cria o projeto do front (`bun create vite ...`) e copia o briefing pra lá como `CLAUDE.md`; o Passo 8 do `docs/ROADMAP.md` ainda diz "HTML + JS puro em `static/`" e precisa ser atualizado se a decisão pelo front separado se mantiver; os dois 500 são buracos da API a tratar no backend; o túnel pro banco não foi aberto.
